# Open ports 80 and 443 through launchd and the Linux unprivileged-port setting

PV now has a privileged helper, which removes the reason ADR 0009 chose `pf`. PV serves the Gateway on the real loopback ports instead of redirecting them. On macOS, the daemon's LaunchAgent declares `127.0.0.1:80` and `127.0.0.1:443` as launchd sockets, so launchd opens them as root and hands them to the unprivileged daemon. On Linux, the helper sets `net.ipv4.ip_unprivileged_port_start=80` in `/etc/sysctl.d/`, so the daemon opens them as the user. Both pass the sockets to Caddy as inherited file descriptors. This removes the redirect layer (`pf` anchors and Linux socket proxies), the Gateway's high ports and the routing health states, and keeps routing working across reboots without repair. The Linux setting lets any local program open ports 80–1023, which is acceptable on a single-user development machine and matches Lerd and rootless Docker and Podman guidance.
